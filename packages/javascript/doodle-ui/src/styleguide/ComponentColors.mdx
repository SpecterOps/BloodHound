        </div>

# Component colors

## Where values live

-   `src/tailwind/colors.ts` defines the shared palette.
-   `src/tailwind/plugin.ts` defines every token as a CSS variable in `:root` (light) and `.dark`.
-   `src/tailwind/preset.ts` maps a subset of those variables to Tailwind utilities, such as `text-main`, `text-light`, `text-disabled`, and `bg-primary`.

## Token usage

Tokens on this page fall into two groups:

-   **Shared tokens** are defined in `plugin.ts` and also mapped in `preset.ts`, so they are available both as CSS variables and as Tailwind utility classes. Use them anywhere.
-   **Component tokens** are used only inside their own component modules. They are available as CSS variables, but they are **not** available as Tailwind utility classes: `bg-tooltip-fill` or `border-card-border` will not generate any CSS.

### Best practices

-   In application code, use shared utilities (for example, `text-main` or `bg-primary`). Do not reference component tokens outside their component; they are implementation details and may be renamed or removed when the component changes.
-   To change how a component looks, use its props or `className` first. Overriding a component token on a wrapper (for example, `[--tooltip-fill:var(--surface)]`) affects everything inside that wrapper, so use it only as a scoped last resort.
-   Inside a component module, read component tokens with an arbitrary value and the `color:` type hint, for example `bg-[color:var(--tooltip-fill)]`. The hint tells Tailwind the variable is a color, so it generates the correct property.
-   Utility names do not always match variable names. `text-inverse` reads `--text-contrast`, while `text-contrast` reads `--contrast`. Check the **Utilities** line in the shared tokens table.
-   When adding a token, define it in both `:root` and `.dark` in `plugin.ts`, prefix it with the component name, and add a row to this page. Add it to `preset.ts` only when it is needed outside a single component; it then becomes a shared token.

## Color reference

Search by component, token name, utility class, referenced variable (for example, `neutral-dark-2` or `text-main`), `colors.ts` path (for example, `palette.neutral.light[500]`), or HEX color. Variable searches match the light and dark references; the `--` prefix is optional.

Each swatch is labeled with its exact `colors.ts` reference. CSS-variable aliases are followed to their source, and matching colors read their values directly from that export. HEX appears only when no export has exactly that color; nearest-color approximations are never used. Inherited values and dimensions remain literal.
